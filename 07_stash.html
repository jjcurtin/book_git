7  Stashing Changes

7.1 A pull that won’t go through

Picture this: you’re in the middle of editing a file — a half-finished thought you’re not ready to commit — when you remember you should pull a teammate’s latest work first.

You run git pull, and Git refuses. Your uncommitted edits are in the way: the pull would overwrite them, so Git stops to protect your work.

git stash is the way out. It sets your unfinished changes aside, hands you a clean working tree, and lets you bring them back when you’re ready.

7.2 The setup: you’re mid-edit

Back in your main copy of the repo, you start tweaking brats.txt — jotting how many brats to buy per person:

cd ~/github/gameday-menu
nano brats.txt
Buy 3 brats per person

You haven’t committed — this is a work in progress:

git status
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
    modified:   brats.txt

7.3 Meanwhile, GitHub has moved on

While you were typing, Sam pushed an update to brats.txt up to GitHub (a different line — the brand to buy).

So the version on GitHub is now ahead of yours, and it touches the same file you’re editing. That’s exactly the situation where a plain pull gets stuck.

7.4 The pull is blocked

You try to grab Sam’s change:

git pull
error: Your local changes to the following files would be overwritten by merge:
    brats.txt
Please commit your changes or stash them before you merge.
Aborting

Git offers two ways forward: commit your changes, or stash them. A half-finished thought isn’t worth a commit yet — so you stash.

7.5 Set it aside: git stash

Tuck your uncommitted changes away:

git stash
Saved working directory and index state WIP on main: 9f8e7d6 Merge: offer both ice cream flavors

Your edits are safely parked, and the working tree is back to the last commit — clean:

git status
On branch main
nothing to commit, working tree clean

Give a stash a label so you remember what it holds: git stash push -m "wip: brat quantities".

7.6 See what’s parked: git stash list

Your set-aside work lives in a stack you can inspect any time:

git stash list
stash@{0}: WIP on main: 9f8e7d6 Merge: offer both ice cream flavors

stash@{0} is the most recent entry. For now there’s just one — which is how you want to keep it.

7.7 Now the pull succeeds

With a clean tree, Git can bring Sam’s change down without stepping on anything:

git pull
Updating 9f8e7d6..e4f5a6b
Fast-forward
 brats.txt | 1 +
 1 file changed, 1 insertion(+)

Your local brats.txt now has Sam’s update — but your own half-finished edit is still waiting in the stash.

7.8 Bring it back: git stash pop

Reapply your parked changes on top of the freshly pulled file:

git stash pop
Auto-merging brats.txt
On branch main
Changes not staged for commit:
    modified:   brats.txt

Dropped refs/stash@{0} (f0a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9)

Your work-in-progress is back on top of Sam’s update, and the stash entry is gone. Finish your thought, then git add and git commit as usual.

If your edits and the pulled change touched the same line, pop reports a conflict — resolve it exactly as in the Conflicts unit.

7.9 A few things to know

  • A stash is local only — it never travels to GitHub. It’s for short-term juggling, not long-term storage.
  • git stash pop reapplies your work and removes the entry; git stash apply reapplies it but leaves the entry in the list.
  • Plain git stash leaves brand-new untracked files behind. Add -u (git stash -u) to sweep those in too.

Good habit: pop a stash soon. A pile of forgotten stashes is hard to untangle later.

7.10 Your turn

ImportantTry it

Stash, sync, and restore:

  1. Edit cheese_curds.txt but don’t commit
  2. Run git stash, then confirm git status is clean
  3. git pull to sync with GitHub
  4. git stash pop to bring your edit back, then finish and commit it

7.11 Where we are

Stashing lets you step away from unfinished work without committing it:

  • git stash parks your uncommitted changes and cleans the working tree
  • git stash pop brings them back; git stash list shows what’s parked
  • It’s the cleanest way to let a blocked git pull go through
