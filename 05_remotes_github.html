5  Remotes in GitHub

5.1 Everything lives on one laptop

So far Bucky’s whole menu — files and history — exists only on his computer.

That is fragile:

  • If the laptop dies, the repo and its history are gone
  • Bucky can’t work on it from another machine
  • He can’t share it or collaborate with teammates

The fix is a copy hosted online that we sync with. That is what GitHub is for.

5.2 GitHub hosts your repo

GitHub is a website that stores Git repositories in the cloud. (GitLab and Bitbucket do the same thing.)

A hosted copy gives you three things:

  • Backup — your work survives a dead laptop
  • Sync — the same project on your laptop, your lab machine, a server
  • Collaboration — teammates can see and contribute

Remember: Git is the tool on your computer; GitHub is a place to host what Git tracks.

5.3 SSH keys: how GitHub knows it’s you

When you push work to GitHub, it has to be sure the push is really from you.

SSH keys are a matched pair:

  • A private key that stays secret on your laptop
  • A public key that you give to GitHub

GitHub matches the two so you never type a password. You set this up once per computer — and you did it before class, so we will just confirm it works.

5.4 Verify your connection

Ask GitHub whether it recognizes your key:

ssh -T git@github.com
Hi buckybadger! You've successfully authenticated, but GitHub does not provide shell access.

That greeting means your key works and you’re ready to push. If you instead get a permission denied error, follow the SSH setup guide or grab a neighbor before we go on.

5.5 Make a home for it on GitHub

In your browser, signed in to GitHub:

  1. Click + (top right) → New repository
  2. Name it gameday-menu to match the local folder
  3. Leave it Public
  4. Do not check “Add a README,” “.gitignore,” or a license
  5. Click Create repository

We skip the README and friends because we already have a repo with history. Starting a second history on GitHub would just collide with ours.

Starting a brand-new project instead? You can make the repo on GitHub first and clone it down — see the Starting a Repo on GitHub appendix.

5.6 Copy the SSH address

The new repo’s page shows setup hints. Find the SSH address (make sure the SSH tab is selected, not HTTPS):

git@github.com:buckybadger/gameday-menu.git

This is the address of your GitHub copy. We will hand it to Git so your laptop knows where to send things.

5.7 Point your repo at GitHub: git remote add

A remote is a named connection to a hosted copy. Add one, using your own address:

git remote add origin git@github.com:buckybadger/gameday-menu.git

origin is the conventional name for your main remote. Confirm it:

git remote -v
origin  git@github.com:buckybadger/gameday-menu.git (fetch)
origin  git@github.com:buckybadger/gameday-menu.git (push)

5.8 Send it up: git push

Push your main branch to the origin remote. The -u flag links your local main to the remote’s main, so Git remembers the pairing:1

git push -u origin main
Enumerating objects: 12, done.
Writing objects: 100% (12/12), 1.1 KiB | 1.1 MiB/s, done.
To github.com:buckybadger/gameday-menu.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.

Reload the GitHub page: your files and every commit are now there. Note that receipts/ and the .tmp files are absent — they were ignored, so they never traveled.

5.9 The everyday loop: pull and push

Because that first push used -u, Git now knows the pairing — so syncing is just two short commands:

  • git pull — bring down changes from GitHub (a teammate’s work, or edits from another machine)
  • git push — send your new commits up

No need to name origin main again — the tracking link set up by -u fills that in. Good habit: pull when you start, push when you finish. And to get the repo onto a brand-new machine, git clone <address> creates the folder, sets up origin, and configures the same tracking automatically — so bare git push/git pull work there right away.

5.10 Your turn

ImportantTry it

Make a change and publish it:

  1. Add a line to desserts.txt with nano (kringle, for the Wisconsin touch)
  2. git add and git commit with a clear message
  3. git push (no need for origin main now)
  4. Refresh your repo on GitHub and watch the new commit appear

5.11 Where we are

Bucky’s menu now lives on GitHub, backed up and shareable:

  • git remote add origin <address> links the local repo to GitHub
  • git push -u origin main sends commits up the first time and sets up tracking; after that, bare git push and git pull are all you need
  • git clone <address> copies a repo onto a new machine (tracking already set up)
ImportantWhat’s next

Working with others means parallel changes — which brings branches and merge conflicts. Those live in the book chapters to explore on your own. Keep the cheatsheet handy.

  1. Prefer not to remember -u? Run git config --global push.autoSetupRemote true once per computer, and Git sets up the tracking link on your first bare git push automatically — no -u needed.↩︎
