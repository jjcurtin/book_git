3  Exploring History

3.1 The menu so far

Bucky has a few commits of history to work with:

git log --oneline
c3d4e5f (HEAD -> main) Add cheese curds and desserts
b2c3d4e Note how many brats to buy
a1b2c3d Add brats to the menu

Your commit IDs will differ from these, and you may also see your cream-puffs commit from the last exercise — all expected.

History is only useful if you can look back at it and recover from mistakes. That is what this unit is about.

3.2 Bucky makes a change he’ll regret

Late at night, Bucky second-guesses the whole plan. Open brats.txt:

nano brats.txt

Add a regrettable third line, then save and exit:

Bratwurst - simmer in beer and onions, then grill
Count: 2 per person (Bucky eats 4)
Swap the brats for a kale salad

In the cold light of game day, this was a mistake. We want the old brats.txt back.

3.3 HEAD points to your latest commit

HEAD is Git’s name for the commit you are currently on — normally your most recent one.

You can count backward from it:

  • HEAD — the latest commit
  • HEAD~1 — one commit before that
  • HEAD~2 — two commits before that

HEAD~1, HEAD~2, … are easy for recent commits. To reach a specific commit further back, copy its ID from git log --oneline rather than counting.

3.4 Review before you restore

Good practice: look at what you are about to throw away. Compare your file to the last commit:

git diff HEAD brats.txt
diff --git a/brats.txt b/brats.txt
index f735c2d..a9c3e21 100644
--- a/brats.txt
+++ b/brats.txt
@@ -1,2 +1,3 @@
 Bratwurst - simmer in beer and onions, then grill
 Count: 2 per person (Bucky eats 4)
+Swap the brats for a kale salad

The only difference from the last commit is the one regrettable line. Safe to discard.

3.5 Undo an uncommitted change: git restore

Throw away the edit and bring back the committed version:

git restore brats.txt

git restore prints nothing on success. Check the result:

cat brats.txt
Bratwurst - simmer in beer and onions, then grill
Count: 2 per person (Bucky eats 4)

The kale line is gone, and git status reports a clean working tree again.

3.6 How git restore picks what to bring back

git restore reads a file from a source and writes it into your working directory.

  • By default the source is the staging area — which matches your last commit unless you have staged something. That is what just undid the uncommitted edit.
  • Point it at any commit with --source (short: -s) to reach back into history.

It overwrites your current working copy with no undo, so review with git diff first.

3.7 Reach back to an older commit

Bucky is curious what the very first, one-line menu looked like. Find that commit’s ID at the bottom of your log:

git log --oneline
...
a1b2c3d Add brats to the menu

Restore brats.txt from that commit — use your own ID (here, a1b2c3d):

git restore --source=a1b2c3d brats.txt
cat brats.txt
Bratwurst - simmer in beer and onions, then grill

Only the working copy changed; the staging area and history are untouched.

3.8 The older version is now an unstaged change

Because the working copy no longer matches the last commit, Git flags it as modified:

git status
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
    modified:   brats.txt

no changes added to commit (use "git add" and/or "git commit -a")

Two choices from here:

  • Keep it: git add + git commit to make the old version the new latest
  • Change your mind: git restore brats.txt snaps back to HEAD

So we all stay in sync for the rest of the lecture, let’s all snap back to HEAD:

git restore brats.txt

3.9 Your turn

ImportantTry it
  1. Add a silly line to cheese_curds.txt with nano
  2. Preview it with git diff HEAD cheese_curds.txt
  3. Discard it with git restore cheese_curds.txt
  4. Peek at the original brats: copy the Add brats to the menu ID from git log --oneline, run git restore --source=<that ID> brats.txt, cat it, then git restore brats.txt to return to the latest

3.10 Where we are

We can now travel through our history:

  • HEAD, HEAD~1, … name past commits
  • git diff HEAD <file> reviews changes since the last commit
  • git restore <file> discards uncommitted edits (from the staging area)
  • git restore --source=<commit> <file> brings back an older version
