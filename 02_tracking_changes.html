2  Tracking Changes

2.1 The rhythm of Git

Every version you save follows the same two-step rhythm:

  • Edit your files as usual
  • git add — mark the changes you want to save
  • git commit — save them as a point in history

Along the way, three commands let you check in:

  • git status — where do things stand?
  • git diff — what exactly changed?
  • git log — what have I saved so far?

2.2 Put the first item on the menu

Bucky starts with the main event. Open a new file with nano:

nano brats.txt

Type one line, then save and exit with Ctrl+X, then Y, then Enter:

Bratwurst - simmer in beer and onions, then grill

Prefer a different editor? Open the file in the RStudio source editor, or use another terminal editor like vim (my preferred editor) — any of them works. These slides use nano. Either way, nothing has been handed to Git yet; we have only written to the folder.

2.3 A new, untracked file

Check in with git status:

git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
    brats.txt

nothing added to commit but untracked files present (use "git add" to track)

Git sees brats.txt but calls it untracked — it is not yet part of the history.

2.4 Step 1 of 2: stage it with git add

Tell Git this file belongs in the next saved version:

git add brats.txt

This puts brats.txt on the stage — the group of changes that will be saved together on your next commit.

git add produces no output when it succeeds. Run git status to see what it did.

2.5 Staged and ready

git status
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
    new file:   brats.txt

Now Git lists brats.txt under Changes to be committed. It is staged, but not yet saved to history.

2.6 Step 2 of 2: save it with git commit

A commit is a permanent point in your history. It needs a short message describing the change:

git commit -m "Add brats to the menu"
[main (root-commit) a1b2c3d] Add brats to the menu
 1 file changed, 1 insertion(+)
 create mode 100644 brats.txt

The -m flag supplies the message. This is our first commit, so Git labels it the root-commit and stamps it with a unique ID (a1b2c3d).

2.7 Working tree clean

git status
On branch main
nothing to commit, working tree clean

Working tree clean means the folder matches the saved history exactly — nothing is waiting to be saved.

2.8 Where your work lives

That two-step dance makes sense once you see the three places your work can be:

Working directory Staging area Repository
Your files as you edit them Changes you have marked to save The permanent history of commits

Two commands move your work to the right along this path.

2.9 git add moves work to the stage

Working directory Staging area Repository
Your files as you edit them Changes you have marked to save The permanent history of commits

git add copies changes from your working directory onto the stage. You choose exactly what goes on.

2.10 git commit records the stage

Working directory Staging area Repository
Your files as you edit them Changes you have marked to save The permanent history of commits

git commit records everything on the stage as one point in history. The extra step is a feature: it lets you group related changes into a single, meaningful commit.

2.11 See your history: git log

git log
commit a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0 (HEAD -> main)
Author: Bucky Badger <bucky@wisc.edu>
Date:   Fri Oct 9 10:15:00 2026 -0500

    Add brats to the menu

Each commit records the full ID, who made it, when, and the message. HEAD marks where you are now.

2.12 Bucky tweaks the brats

How many to buy? Reopen the file:

nano brats.txt

Add a second line, then save and exit:

Bratwurst - simmer in beer and onions, then grill
Count: 2 per person (Bucky eats 4)

Save the file, then check what Git thinks.

2.13 A tracked file, now modified

git status
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
    modified:   brats.txt

no changes added to commit (use "git add" and/or "git commit -a")

This time Git already knows brats.txt, so it reports it as modified rather than untracked.

2.14 What exactly changed? git diff

Came back from the stadium and forgot what you edited? Ask Git:

git diff brats.txt
diff --git a/brats.txt b/brats.txt
index 83db48f..f735c2d 100644
--- a/brats.txt
+++ b/brats.txt
@@ -1 +1,2 @@
 Bratwurst - simmer in beer and onions, then grill
+Count: 2 per person (Bucky eats 4)

Git colors the output: added lines show in green with a +, and removed lines would show in red with a -.

Prefer a visual, side-by-side diff? The Using Meld for Diffs appendix sets up git difftool to open these comparisons in Meld.

2.15 Stage and commit the edit

Same two steps as before:

git add brats.txt
git commit -m "Note how many brats to buy"
[main b2c3d4e] Note how many brats to buy
 1 file changed, 1 insertion(+)

That is the whole rhythm: edit → add → commit. You will do it hundreds of times.

2.16 One commit, two new files

The menu grows. Create two more files, one at a time:

nano cheese_curds.txt
Fried cheese curds from the Union - 2 baskets
nano desserts.txt
Babcock ice cream - chocolate and Union Blend
git status
Untracked files:
    cheese_curds.txt
    desserts.txt

2.17 Stage both at once

These two go together, so stage them in one step:

git add cheese_curds.txt desserts.txt

Preview what is staged with git diff --staged (plain git diff looks only at unstaged changes):

git diff --staged
diff --git a/cheese_curds.txt b/cheese_curds.txt
new file mode 100644
@@ -0,0 +1 @@
+Fried cheese curds from the Union - 2 baskets
diff --git a/desserts.txt b/desserts.txt
new file mode 100644
@@ -0,0 +1 @@
+Babcock ice cream - chocolate and Union Blend

2.18 Commit them together

Both new files land in one commit:

git commit -m "Add cheese curds and desserts"
[main c3d4e5f] Add cheese curds and desserts
 2 files changed, 2 insertions(+)
 create mode 100644 cheese_curds.txt
 create mode 100644 desserts.txt

This is why add and commit are separate steps: you decide what belongs together.

Later, we will learn how to undo a commit so best to stage and commit edits that represent some block of changes that belong together for some goal in your development/analysis workflow

2.19 The story so far: git log --oneline

Full git log gets long fast. The --oneline flag gives one row per commit:

git log --oneline
c3d4e5f (HEAD -> main) Add cheese curds and desserts
b2c3d4e Note how many brats to buy
a1b2c3d Add brats to the menu

You can also limit the count: git log -2 shows just the two most recent commits.

Name a file to see only the commits that changed it — handy when you need to track down an error in one file:

git log --oneline brats.txt
b2c3d4e Note how many brats to buy
a1b2c3d Add brats to the menu

The cheese curds and desserts commit drops out — it never touched brats.txt. (Add -- before the name, git log --oneline -- brats.txt, if Git confuses it with a branch.)

2.20 Writing good commit messages

Your future self reads these. Aim for the middle ground:

Message Verdict
changes Too vague — says nothing
Added “Fried cheese curds from the Union - 2 baskets” to cheese_curds.txt Too verbose — just repeats the file
Add cheese curds and desserts Captures the meaning, briefly

Keep the first line under about 50 characters and describe the change, not the literal text.

2.21 Your turn

ImportantTry it

Bucky wants cream puffs. On your own:

  1. Add a line to desserts.txt for cream puffs
  2. Check what changed with git diff
  3. Stage it with git add, then git commit with a clear message
  4. Confirm it landed with git log --oneline

2.22 Where we are

We can now build history on purpose:

  • git add stages changes; git commit saves them
  • git status shows where things stand
  • git diff shows what changed; git log shows what we saved
