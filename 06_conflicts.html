6  Conflicts

6.1 When does a conflict happen?

A conflict happens when two commits change the same line of the same file in different ways, and Git can’t tell which one is right.

It usually surfaces when you bring two lines of work together — for us, when you git pull and someone else has edited the same line you did.

Conflicts are normal, not a disaster. Git just needs you, the human, to decide what the final version should say.

6.2 Our setup: two people, one repo

Bucky’s menu is on GitHub. His co-organizer Sam clones it to help plan dessert.

To follow along on your own, clone a second copy into a different folder — it stands in for Sam’s computer:

cd ~/github
git clone git@github.com:buckybadger/gameday-menu.git gameday-menu-sam

Now there are two working copies of the same repo: your original gameday-menu and gameday-menu-sam.

6.3 Sam changes a line and pushes

In Sam’s copy, edit the ice cream line in desserts.txt:

cd ~/github/gameday-menu-sam
nano desserts.txt
Babcock ice cream - Orange Custard Chocolate Chip

Then commit and push it up to GitHub:

git add desserts.txt
git commit -m "Pick Orange Custard Chocolate Chip ice cream"
git push

GitHub now has Sam’s version of that line.

6.4 Meanwhile, you change the same line

Back in your original copy — not knowing what Sam did — edit the same line differently:

cd ~/github/gameday-menu
nano desserts.txt
Babcock ice cream - Union Blend
git add desserts.txt
git commit -m "Pick Union Blend ice cream"

Both commits look fine on their own. The trouble starts when they meet.

6.5 The push is rejected

Try to push your version:

git push
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'github.com:buckybadger/gameday-menu.git'
hint: Updates were rejected because the remote contains work that you do
hint: not have locally. Integrate the remote changes before pushing again.

GitHub is protecting Sam’s commit. It’s telling you to pull first and reconcile before you can push.

6.6 Pull brings the conflict to light

git pull
Auto-merging desserts.txt
CONFLICT (content): Merge conflict in desserts.txt
Automatic merge failed; fix conflicts and then commit the result.

Git merged everything it could, but it can’t auto-merge that one line — you both rewrote it. It stops and hands the decision to you.

6.7 git status points you to the problem

git status
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add <file>..." to mark resolution)
    both modified:   desserts.txt

both modified is the tell-tale sign of a conflict. If you ever feel stuck, git merge --abort backs out and returns you to before the pull.

6.8 Reading the conflict markers

Open desserts.txt. Git has inserted markers around the clashing lines:

<<<<<<< HEAD
Babcock ice cream - Union Blend
=======
Babcock ice cream - Orange Custard Chocolate Chip
>>>>>>> 3f9a1c2 (Pick Orange Custard Chocolate Chip ice cream)
  • Between <<<<<<< HEAD and ======= is your version
  • Between ======= and >>>>>>> is the incoming version from GitHub

6.9 Resolve it: you decide

Edit the file so it reads exactly how you want, and delete all three marker lines. Bucky wants both flavors:

Babcock ice cream - Union Blend and Orange Custard Chocolate Chip

You are free to keep your version, keep theirs, combine them, or write something new. Just make sure every marker (<<<<<<<, =======, >>>>>>>) is gone — a file can have several conflicts, so check the whole thing.

6.10 Mark it resolved and commit

Once the markers are gone, stage the file to tell Git the conflict is settled, then commit:

git add desserts.txt
git commit -m "Merge: offer both ice cream flavors"
git push

That commit records the resolution. Now push succeeds, and Sam can git pull to pick up the agreed-on version. The conflict is behind you.

6.11 Avoiding conflicts

You can’t prevent them entirely, but a few habits make them rare and small:

  • Pull before you start working, so you begin from the latest version
  • Push often, in small focused commits
  • Coordinate with collaborators about who is editing what

And when one does happen — read the markers, decide, delete them, add, commit. That’s the whole skill.

6.12 Your turn

ImportantTry it

Make a conflict on purpose and resolve it:

  1. In gameday-menu-sam, change a line in brats.txt, commit, and push
  2. In gameday-menu, change the same line differently and commit
  3. git push (watch it get rejected), then git pull to trigger the conflict
  4. Edit brats.txt to settle it, remove the markers, then git add, git commit, and git push

6.13 Where we are

Conflicts are a skill, not a catastrophe:

  • They arise when two commits change the same line
  • git pull surfaces them; both modified in git status flags them
  • Edit the file, remove the markers, then git add and git commit
