1  Introduction and Setup

1.1 Why are we here?

By the end of this hour you will be able to:

  • Explain what version control is and why it matters for data science
  • Put a project folder under Git and track changes to it
  • Save versions with meaningful messages, and look back at your history
  • Tell Git to ignore files it should not track
  • Push your work to GitHub to back it up and share it

We will build one project together, start to finish: Bucky’s game-day menu.

You’ll build this repo along with me the whole hour — including the Your turn moments, where you try a step on your own before we regroup.

1.2 What is version control?

Version control keeps track of changes you make to files over time.

It lets you:

  • Go back to any earlier version of a file
  • Keep only one copy in your folder (not ten copies with different names)
  • See what changed, when, and why
  • Work with others without emailing files back and forth
  • Keep the same project synced across computers

1.3 You have probably done this the hard way

How many of these folders have you lived in?

analysis.R
analysis_v2.R
analysis_final.R
analysis_final_FINAL.R
analysis_2026-10-01.R
analysis_2026-10-01_jjc.R

You cannot tell what changed between any two of them, and they all pile up in the same folder.

1.4 Git fixes this

With Git, you keep one analysis.R in your folder.

Git quietly stores the full history behind the scenes. At any point you can:

  • Ask “what did this file look like last Tuesday?”
  • Read the note you left yourself explaining each change
  • Restore an older version without losing your current work

“Your closest collaborator is you six months ago, and they don’t answer email.”

Git is how you leave notes for that person.

1.5 Git is not GitHub

A point of confusion worth clearing up right away:

What it is Where it lives
Git The version-control software On your computer
GitHub A website that hosts Git repositories In the cloud

You can use Git with no internet at all. GitHub is where you put a copy to back it up, share it, and collaborate. We get there at the end of the hour.

1.6 Our running example: Bucky’s game-day menu

Bucky Badger is planning the food for a game-day tailgate, and the menu keeps changing.

We will keep the plan in a folder called gameday-menu, with a file per part of the spread:

  • brats.txt
  • cheese_curds.txt
  • desserts.txt

As the menu evolves, we will use Git to track every change, so Bucky can always see what the plan looked like last week.

1.7 What you should already have

This lecture assumes two things are done:

  1. Git is installed on your laptop
  2. You have a GitHub account

If either is missing, follow the setup guide and catch up with a neighbor:

https://carpentries.github.io/workshop-template/#git

Everything today happens in a terminal (Git Bash on Windows; Terminal on macOS/Linux). Git commands all start with the word git.

RStudio also has a built in terminal. I use it rather than a separate terminal for git and file management when I am working on analysis code for a project. Its up to you!

1.8 Tell Git who you are

Git stamps every saved version with a name and email. Set yours once per computer:

git config --global user.name "Your Name"
git config --global user.email "you@wisc.edu"

Use your own name and email, not Bucky’s. The email should match the one on your GitHub account.

The --global flag means “use this for every project on this computer,” so you only do it once.

1.9 Check that it worked

You can confirm your settings at any time:

git config --list

Look for your user.name and user.email in the output:

user.name=Bucky Badger
user.email=bucky@wisc.edu
init.defaultBranch=main

If you made a typo, just run the config command again to overwrite it.

1.10 Make a folder for the project

Create a folder for Bucky’s menu and move into it.

I prefer to keep all of my git repos at one location (~/github)

mkdir github
cd github

mkdir gameday-menu
cd gameday-menu

Right now this is just an ordinary folder. Git is not watching it yet.

1.11 Turn the folder into a repository

A repository (or “repo”) is a folder that Git is tracking, along with its full history.

Turn the current folder into one with a single command:

git init
Initialized empty Git repository in /home/bucky/github/gameday-menu/.git/

Git created a hidden .git folder to store the history. You never edit it by hand; Git manages it for you.

1.12 Meet git status

git status is the command you will run the most. It tells you where things stand.

git status
On branch main
No commits yet
nothing to commit (create/copy files and use "git add" to track)

1.13 Reading that message

Three things Git just told us:

  • On branch main — the default line of work (more on branches another day)
  • No commits yet — we have no saved history in this repo
  • nothing to commit — the folder is empty, so there is nothing to track

Notice the hint: use “git add” to track. Git is telling us the next step.

1.14 Where we are

We have:

  • Confirmed Git knows who we are
  • Created the gameday-menu folder
  • Turned it into a Git repository with git init
  • Learned to check in with git status
