Introduction to Git and Github

Git and GitHub are the tools data scientists use to track changes to their work, recover earlier versions, and collaborate without overwriting each other. This book is a hands-on introduction, built around a single running example that grows from an empty folder into a shared repository on GitHub.

Where these materials come from

These materials are based on the Version Control with Git video series produced by the UW-Madison Data Science Facilitators at the Data Science Institute. We are grateful for their work.

The book is designed as an alternative to watching the videos: the same material, in a form you can read quickly, follow along with during a workshop, and return to later when a specific question comes up — without scrubbing through an hour of video to find the one command you need.

Where it helps, we have also updated the workflows to use current Git commands:

  • To restore a previous version of a file, we use git restore rather than the older git checkout.
  • To move between branches, we use git switch rather than git checkout.

These newer commands each do one job, which makes them clearer and harder to misuse than the older, overloaded git checkout.

How this book is organized

The book has seven units plus a few reference appendices.

  • Units 1–5 are the core everyday workflow. They are covered live in a one-hour, hands-on workshop.
  • Units 6–7 (Conflicts and Branches) go beyond the live hour and are here for you to explore on your own afterward.

Every unit also has a companion slide deck, published on Posit Connect Cloud (Units 1–5 are the decks we present live):

The appendices cover one-time setup you should finish before the workshop — installing Git on Windows (Windows users only) and connecting to GitHub with SSH keys — and a cheatsheet at the end collects every command in one place for quick reference.

How to use this book

Git is best learned by doing. As you read, follow along in a terminal — Git Bash on Windows, or Terminal on macOS/Linux, or even the terminal in RStudio — and type the commands yourself. Everything builds one running example (Bucky Badger’s game-day menu), so the repository you create grows right alongside the book.

A few conventions to know:

  • Commands you type appear in shaded code blocks, with the output Git prints shown just below them.
  • Your turn boxes are short challenges to try on your own before moving on.
  • Keep the cheatsheet open in another tab for quick reference.
