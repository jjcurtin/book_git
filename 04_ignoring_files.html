4  Ignoring Files

4.1 Not everything belongs in Git

Git is built for tracking the files you author. Some files are better left untracked:

  • Scratch and throwaway files — temporary notes, drafts, scratch output
  • Large or raw data — bloats the repo and rarely changes
  • Binary files — Git can’t meaningfully diff a photo or .xlsx; it just stores a full copy each time
  • Secrets — API keys, passwords, credentials should never be committed

Instead of eyeballing git status and carefully avoiding them, we can tell Git to ignore them for good.

4.2 Bucky’s folder gets cluttered

Game-day prep leaves a mess: scratch files and a folder of receipt photos.

touch scratch.tmp shopping-draft.tmp
mkdir receipts
touch receipts/costco.jpg receipts/metcalfe.jpg

The .tmp files are throwaway scratch; the receipts/ photos are big, binary, and nobody needs them in the menu’s history.

4.3 Git sees the clutter

git status
On branch main
Untracked files:
  (use "git add <file>..." to include in what will be committed)
    receipts/
    scratch.tmp
    shopping-draft.tmp

nothing added to commit but untracked files present (use "git add" to track)

Git keeps nagging about files we never intend to track — and worse, we might commit them by accident.

4.4 Create a .gitignore

Git reads a file named .gitignore and ignores anything that matches a pattern in it. Create one:

nano .gitignore

Add two patterns, then save and exit:

*.tmp
receipts/

*.tmp matches any file ending in .tmp; the trailing slash in receipts/ matches that whole folder and everything inside it.

4.5 The clutter disappears

git status
On branch main
Untracked files:
  (use "git add <file>..." to include in what will be committed)
    .gitignore

nothing added to commit but untracked files present (use "git add" to track)

The scratch files and receipts/ are gone from the list. The only thing Git still sees is .gitignore itself.

4.6 Track the .gitignore itself

Commit .gitignore so the rules travel with the project:

git add .gitignore
git commit -m "Ignore scratch files and receipts"
[main d4e5f6a] Ignore scratch files and receipts
 1 file changed, 2 insertions(+)
 create mode 100644 .gitignore

Tracking it means anyone who clones the repo — including future you on another computer — ignores the same files automatically.

4.7 Ignored means ignored

New files that match keep getting ignored, with no extra work:

touch results.tmp
git status
On branch main
nothing to commit, working tree clean

And if you try to add an ignored file, Git stops you:

git add scratch.tmp
The following paths are ignored by one of your .gitignore files:
scratch.tmp
hint: Use -f if you really want to add them.

That warning is a feature. If you ever truly need to track one, git add -f forces it.

4.8 Common things to ignore

For data science projects, a .gitignore usually covers:

  • Secrets — .env, API keys, credential files
  • Large or raw data — data/, *.csv, *.parquet
  • Generated output — rendered reports, figures, caches
  • Tool cruft — .Rhistory, .RData, .Rproj.user/, __pycache__/

Many languages and editors publish starter .gitignore files you can copy from — GitHub even offers one when you create a repo.

Already committed a secret by accident? Ignoring it now won’t remove it from past history — see the “Removing Sensitive Data from a Repository” appendix.

4.9 Your turn

ImportantTry it

Bucky keeps a private budget spreadsheet in the folder:

  1. Create it with touch budget.xlsx
  2. Confirm Git sees it with git status
  3. Add a pattern to .gitignore so Git ignores .xlsx files
  4. Run git status again — it should be gone. Then git add and git commit your updated .gitignore

4.10 Where we are

Bucky’s repo now ignores the clutter:

  • .gitignore lists patterns for files Git should skip
  • Patterns like *.tmp and receipts/ match files and folders
  • We commit .gitignore so the rules are shared
