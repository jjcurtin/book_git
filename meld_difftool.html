Appendix C — Using Meld for Diffs

The lessons show differences between versions of a file with git diff, which prints its output right in the terminal. That is quick for a line or two, but hard to read once changes get larger. Meld is a free, graphical diff tool that shows the two versions side by side, with changes highlighted and lined up — much easier to scan than terminal output.

This appendix installs Meld and sets it up as Git’s default difftool, so you can open any git diff in Meld instead. It is optional but recommended. Plan on about ten minutes.

Note

Meld opens a graphical window, so it only works where you have a desktop. On a headless server or a terminal-only remote session, keep using plain git diff.

C.1 Step 1: Install Meld

Pick the instructions for your operating system, then confirm the install at the end.

C.1.1 Windows

Download the installer from meldmerge.org and run it. You can accept the defaults on every screen. The installer adds Meld to your PATH so that Git Bash can find it.

C.1.2 macOS

The simplest route is Homebrew:

brew install --cask meld

If you do not use Homebrew, download the .dmg from meldmerge.org and drag Meld into your Applications folder. (With the .dmg route, the meld command may not be on your PATH; Homebrew sets that up for you, which is why it is the easier option here.)

C.1.3 Linux

Install from your distribution’s package manager:

# Debian / Ubuntu
sudo apt install meld

# Fedora
sudo dnf install meld

C.1.4 Confirm it worked

In your terminal (Git Bash on Windows), check that Meld is on your PATH:

meld --version
meld 3.22.0

A version number means Git will be able to launch it.

C.2 Step 2: Set Meld as Git’s difftool

Tell Git to use Meld whenever you run git difftool. These three commands write the settings to your global Git configuration, so you only do this once per computer:

git config --global diff.tool meld
git config --global difftool.prompt false
git config --global difftool.meld.cmd 'meld "$LOCAL" "$REMOTE"'
  • diff.tool meld makes Meld the default difftool.
  • difftool.prompt false skips the “Launch meld?” confirmation before each file.
  • difftool.meld.cmd tells Git how to call Meld, with the two versions as its panes.
Note

Use single quotes around the cmd value. They keep $LOCAL and $REMOTE as literal text in your config file — Git fills them in with the actual file versions each time it runs.

These commands edit the .gitconfig file in your home folder. If you prefer to edit it by hand, the equivalent block is:

[diff]
    tool = meld
[difftool]
    prompt = false
[difftool "meld"]
    cmd = meld "$LOCAL" "$REMOTE"

C.3 Step 3: Use it

Anywhere the lessons use git diff, you can swap in git difftool to open the comparison in Meld instead:

Command What Meld shows
git difftool <file> Your uncommitted copy vs. the last commit
git difftool <commit> <file> A past version vs. your current copy
git difftool HEAD HEAD~2 <file> The latest commit vs. two commits back
git difftool <hash1> <hash2> <file> Two specific past versions, side by side

Meld opens a window with the two versions aligned. Close the window to return to the terminal; with difftool.prompt false set, Git moves on to the next file (if any) on its own.

Meld is also handy on its own, outside of Git: launch it and pick any two files to compare — for example, a document in your repo against an edited copy a collaborator emailed you.

C.4 Optional: use Meld to resolve merge conflicts

Meld can also help with the merge conflicts from the Conflicts unit, showing your version, the incoming version, and the merged result together. To set it up as Git’s mergetool:

git config --global merge.tool meld
git config --global mergetool.prompt false
git config --global mergetool.meld.cmd 'meld "$LOCAL" "$MERGED" "$REMOTE" --output "$MERGED"'

Then, when a git pull or git merge reports a conflict, run:

git mergetool

Meld opens with the merged file in the center pane. Edit it until it reads how you want, save, and close. Then finish the merge the usual way with git add and git commit.
